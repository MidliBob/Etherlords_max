
# Демиурги / Etherlords I — native hi-res mod

Проект реверс-инжиниринга и моддинга: добавить игре «Демиурги» (Etherlords I, Nival/1C,
2001, рус. патч 1.07) **нативную поддержку современных разрешений** (16:9, 1440p, 4K)
без внешних обёрток (dgVoodoo/DxWnd).

> Сама игра вами приобретается отдельно. Данный проекта только создает бинарник, который сможет запускать ее на современных мониторах в их родном разрешении. Все инструменты применяются к **вашей собственной**
> копии `Etherlords`. Купите/возьмите игру легально (GOG/Steam/ваш диск).

## Быстрый старт — native v6

1. Скопируйте `tools/patch_native_v3.py` **в папку игры** (где лежит
   `Etherlords.exe`).
2. Запустите его — двойным кликом или из консоли: `python patch_native_v3.py`.
   Скрипт найдёт `Etherlords.exe` рядом (или в текущем каталоге), сверит с
   анализируемым билдом (рус. 1.07, sha256 `409d3e08…`), прогонит самотесты и
   создаст рядом **`Etherlords_native_v6dbg.exe`**.
3. **Запускайте игру через `Etherlords_native_v6dbg.exe`** — переименований и
   замен файлов не нужно: оригинальный `Etherlords.exe` не трогается (он же
   откат). В `settings.ini` выставьте своё `VideoResolution=WxH` (например,
   1600x900).

Нужны Python 3.8+ и `pip install capstone`. На Windows при запуске двойным
кликом окно не закроется сразу — виден результат и ошибки самотестов.

Каждая сборка с 0.0.8 содержит debug-логгер: после запуска в папке игры
появляется `el_evt.log` (последний сеанс, ≤ ~880 КБ). Если UI съезжает/кнопки
не работают — пришлите этот файл (разбор:
`python3 tools/decode_evtlog.py el_evt.log [vtable]`). Сырой лог — бинарный,
загрузчики чатов/почты его браковать; поэтому положите `tools/evt2txt.py`
в папку игры и запустите — получится чисто текстовый `el_evt_decoded.txt`
(с шапкой: разрешение сеанса, счётчики рекордов), его и прикрепляйте
(расширение любое). Фикс колеса ждёт полевой
приемки — протокол в `docs/09` §5.

Из корня репозитория (полный CLI; `--out` — свой путь, `--check` — только
проверка, `--no-logger` — чистый release `Etherlords_native_v6.exe`):

```bash
python3 tools/patch_native_v3.py /путь/к/вашему/Etherlords.exe               # -> Etherlords_native_v6dbg.exe (с логгером)
python3 tools/patch_native_v3.py /путь/к/вашему/Etherlords.exe --no-logger   # -> Etherlords_native_v6.exe (чистый release)
```

## Безопасный базис (раскладка 1024x768, без масштабирования)

Даёт рабочие кнопки и раскладку 1024x768 на любом разрешении (UI не растянут, но жив):

```bash
python3 tools/patch_layout.py /путь/к/вашему/Etherlords.exe   # -> Etherlords_layout1024.exe
# сделать бэкап своего Etherlords.exe и положить результат под его именем
```

## Статус native (v6 — актуальный)

- v2 чинил главное меню, но полевая приемка показала: меню сохранения/загрузки и
  глобальная карта съезжают, hover колеса команд правее нарисованного. Причины
  раскрыты статически (docs/09): контролы, создаваемые после Init (AddControl
  0x58bbc0), собственный массив спрайтов CButtonList ([+0x1c0], шаг 0x34),
  design-константы экранов (блок 0x8295xx, хардкод-рамка CSelectMission).
- **v3 РЕАЛИЗОВАН** (`tools/patch_native_v3.py`): scale-on-create (H4) с
  маркер-протоколом `(nibble[+0x14c]&0xC)==0x4` (идемпотентность пост-прохода),
  масштабирование спрайт-rect'ов CButtonList в scale_one, идемпотентный
  пересчёт design-констант меню сохранений (H5a/H5b), масштаб рамки
  CSelectMission (H6). Прогоны v3/v4 дали материал: post-mortem v4 (регресс H7:
  входы set_rect уже native) → **v5** = откат H7/колонок; для колеса нужен
  runtime-лог: сборка `--debug` пишет el_evt.log (set_rect/OnLayoutChange),
  разбор tools/decode_evtlog.py (docs/09, дополнения v3.1 и v4→v5).
- **v6 РЕАЛИЗОВАН** (тот же сборщик; docs/09, доп. v5→v6): по el_evt.log
  (1965 записей) найдена причина съезда колеса — design-глобалы adv-экрана
  0x827e70/0x827e80 (читаются fn 0x5036xx, пишутся в hit-цепочку, визуал не
  двигается). Пост-проход масштабирует их при k!=1 (тест T3b). Верификация
  release-сборки: 10 сайтов, cave 1766/2474, capstone-аудит 418 инструкций,
  дифф-аудит, интерпретатор T1–T7 + T3b/T5c/T6b (56 проверок, все зелёные).
  Фикс колеса ждёт полевой приемки (docs/09 §5). Остаточные проблемы: тексты
  строк списка сохранений (кэш CTextArray в design-координатах), позиция
  превью сохранений (docs/09 §3, доп. v3.1).
- Сборщик с 0.0.8: логгер H8/H9 (set_rect/OnLayoutChange → `el_evt.log`) встроен
  ПО УМОЛЧАНИЮ в каждую сборку → `Etherlords_native_v6dbg.exe`; лог усекается на
  каждом запуске (всегда = последний сеанс), лимит 20000 рекордов (~880 КБ);
  разбор `tools/decode_evtlog.py`. `--no-logger` → `Etherlords_native_v6.exe`
  (чистый release, байт-в-байт как v6 из 0.0.6). Функциональные тесты теперь
  прогоняются для любой сборки (T1–T8, 67 проверок в сборке с логгером).
  H10 (логгер hit-test) по-прежнему не включён — не вмещался в cave
  (docs/09, доп. 0.0.6 и 0.0.8).

## Статус native (v2, исторический)

- Причина найдена: у UI две зашитые раскладки (800x600 / 1024x768); при любом другом
  разрешении вызов применения раскладки пропускается (`docs/03`).
- **Механизм профилей раскрыт полностью (`docs/07`):** раскладка — данные `Controls.reg`
  (Left/Top/Width/Height + `ShiftX/ShiftY` второго профиля); переключение = сдвиг RECT'ов
  контролов (`OffsetRect`), НИКАКОГО масштабирования в движке нет. Объект контрола:
  record[0/1] {X,Y,sX,sY} @+0x18c/+0x19c, active @+0x1ac, hit-rect @+0x154, маска @+0x150,
  визуал @+0x148; relayout `0x591250`, OnLayoutChange `0x5912e0`, hit-test `0x58fb70`,
  apply_layout `0x59fcb0` (настоящие VA; docs/02–06 сдвинуты на +0x400000).
- Модель согласованности (уточнена по наблюдениям): потребителей координат **три** —
  отрисовка (baked-поля раскладки), hover (rect, native), click (требует совпадения
  hover-элемента и baked-раскладки). Клики живы **только при rect == baked** (`docs/04`).
  Проверено: клик не работает ни по периметру (hover есть), ни по нарисованным кнопкам.
- v1 (подмена экран-rect) ломал это согласование → регрессия (`docs/05`).
- Целевые native-позиции = зоны hover-подсветки по периметру: бесплатный критерий приемки.
- **v2 РЕАЛИЗОВАН** (`tools/patch_native_v2.py`, подробности `docs/08`): форс
  apply_layout(1) + трамплин живых W/H в apply_layout + пост-проход списка `[0x82b968]`
  с масштабированием RECT'ов (+0x154/+0x164/+0x174), визуала (+0x148: rect'ы
  `[[subnode+0x10]+0x40/+0x18]`, включая текст) и active (+0x1ac/+0x1b0). Пиксельные
  маски (+0x150) НЕ перемасштабируются — вместо этого hit-test делит dx/dy обратно
  в design-пространство (mask-fix), сохраняя пиксельную точность. Records/сдвиги
  профилей не трогаются (идемпотентность relayout сохранена).
  Верификация сборки: контрольные байты сайтов, capstone-аудит cave (167 инструкций),
  аудит диффа (только сайты+cave) и прогон байтов cave на встроенном интерпретаторе
  i386 (тесты T1–T4) — все зелёные. Осталось: runtime-приемка на Windows (`docs/08` §6).

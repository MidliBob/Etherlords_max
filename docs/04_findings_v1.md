# Etherlords.exe (Демиурги, рус. 1.07) — карта находок под native hi-res

Бинарь: `Etherlords.exe`, 4 313 088 байт, base `0x400000`, линкер VC6 (6.0),
TimeDateStamp 1026902848. Секции: `.text` 3,49 МБ (ent 6.56), `.rdata`, `.data`, `SGI_STL_`, `.rsrc`.
Соответствие file→VA: для `.text` **VA = file + 0x800000**.

Весь игровой код — в `Etherlords.exe`. `etherlords.dll` (5 МБ) — это в основном
упакованные данные (`.data` 2,27 МБ, ent 0.84), кода там ~45 КБ.
`2DintMMX.dll` / `3DfpFPU.dll` — программные (software) рендереры, используются только
при `Video=0/1`; при `Video=2` (ваш случай) рендер аппаратный, внутри `Etherlords.exe`.

Графика: **DirectDraw** (импорт `DDRAW.dll: DirectDrawCreateEx, DirectDrawEnumerateExA`).
Режим ставится через vtable `IDirectDraw7::SetDisplayMode` = `call [reg+0x54]` (~30 сайтов),
список режимов — `EnumDisplayModes` = `call [reg+0x20]`.

## A. Разбор `VideoResolution` — белого списка НЕТ

Строка `VideoResolution` @ file `0x3ee93c`. Чтение @ VA `0x82db92`:

```
push 0x7ee93c            ; "VideoResolution"
call 0x805f50            ; получить значение из ini, разбить на токены
cmp  [esp+0x18], 2       ; токенов должно быть ровно 2 ("W" и "H")
jne  skip
mov  eax,[edx]     ; токен[0]
call 0xaeb921      ; atoi  -> Width
mov  [esi+0x28], eax     ; ОБЪЕКТ НАСТРОЕК + 0x28 = Width
mov  eax,[eax+4]   ; токен[1]
call 0xaeb921      ; atoi  -> Height
mov  [esi+0x2c], eax     ; ОБЪЕКТ НАСТРОЕК + 0x2c = Height
```

**Вывод:** значение берётся из ini как есть, без валидации против списка.
Поэтому `VideoResolution=1600x900` уже работает на старте. Stage 1 (clamp) — не нужен.
Запись обратно (save) — VA `0x82e435` через `%dx%d` (`0x7ee990`).

## B. Хардкоды старых разрешений (то, на что вы жаловались)

Найдены паттерны `push 600; push 800` (f(...,800,600)) — дефолт/фолбэк 800x600:

| Сайт | VA | Контекст |
|---|---|---|
| #1 | `0x59ab31` | `push 600; push 800; push edi; push edi; push ptr; call [IAT 0x756428]` — инициализация окна/поверхности 800x600 |
| #2 | `0x59bd0a` | `push 600; push 800; push 0; push 0; push ptr; call [IAT 0x756428]` — то же в (0,0) |

Рядом с #2 — **сравнения с 1024x768**:

```
0x59bd3c  cmp ecx, 0x400      ; 1024
0x59bd42  jne  ...
0x59bd47  cmp eax, 0x300      ; 768
0x59bd4c  jne  ...
```

То есть в этом же модуле есть ветвление «если режим == 1024x768». Это и есть источник
«зашитых старых разрешений»: дефолт 800x600 + особая ветка 1024x768.

## C. Константы соотношения сторон (проекция / UI-масштаб)

| Значение | Тип | file | Примечание |
|---|---|---|---|
| `1.3333334` (4/3) | float imm | `0x46f32` | `push 0x3faaaaab` → аргумент в `call 0x41fd00` (построение матрицы/вьюпорта) |
| `0.75` (3/4) | mov imm | `0x52b30` | кладётся в `[esi+0x20]`, рядом `[esi+0x24]`,`[esi+0x28]`,`[esi+0x2c]` — поля камеры/проекции |
| `0.75` | float | `0x356f98`, `0x3888fa`, `0x3e3f26`, `0x3ff1cc` | .rdata/.data — данные |
| `0.75` double | double | `0x297426`, `0x364268`, `0x3f2f48` | данные |

Сайт `0x446f31` (`push 0x3faaaaab`) и `0x452b2f` (`mov eax,0x3f400000`) — самые
правдоподобные точки, где aspect зашит вместо вычисления `W/H`.

## D. Что это значит для «нативной поддержки»

1. Разрешение из ini уже применяется без clamp → **проблема не в старте, а в раскладке/aspect**.
2. Дефолт 800x600 и ветка «==1024x768» в модуле ~`0x59b000` — кандидаты на то, чтобы
   вместо констант брать текущие W/H из объекта настроек (`+0x28/+0x2c`).
3. Aspect 4/3 зашит в двух местах (`0x446f31`, `0x452b2f`) → при 16:9 3D будет тянуться,
   пока их не заменить на динамический `W/H`.
4. UI-центрирование (диалоги, главное меню) — отдельный слой; по скриншотам Etherlords II
   он использует абсолютные координаты. В Etherlords I нужно локализовать отдельно
   (искать `cmp/shr` против 1024/768 и паттерн `(screenW-w)/2`).

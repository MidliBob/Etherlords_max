# Etherlords.exe — срез 2: причина «зашитых разрешений» найдена точно

## Измеренная раскладка (ваши скриншоты, template matching, OpenCV)

Позиции одних и тех же элементов UI при 1024x768 и 1600x900:

| Элемент | 1024x768 | 1600x900 | Что это значит |
|---|---|---|---|
| Миникарта (top-left) | (860, 4) | (636, 4) | правый край 1010 → **786**: привязка справа к **1024 → 800** |
| Командное колесо (top-left) | (810, 600) | (586, 600) | правый край 1000 → **776**: справа к **800**; y не изменился (=600) |
| Нижняя панель (top-left) | (20, 742) | (20, 574) | низ 766 → **598**: привязка снизу к **768 → 600** |
| Фон главного меню | весь экран | блок 1024x768 в (0,0), дальше серый clear | бэкбуфер = реальные 1600x900, арт рисуется нативно 1024x768 |
| Кнопки главного меню (центр колонки) | x≈512 (=1024/2) | x≈400 (=**800**/2) | центр по горизонтали считается от **800** |

**Вывод из измерений:** бэкбуфер/очистка используют реальный размер (1600x900), а вся
привязка UI считает экран равным **800x600** (дефолт), местами арт — 1024x768.

## Причина в коде (функция выбора раскладки UI, file ~0x19bd28)

```
0x99bd28  mov  eax,[0x825de8]        ; глобальный объект дисплея
0x99bd2d  mov  ecx,[eax+0x14]
0x99bd30  test ecx,ecx
0x99bd34  je   bd61                  ; null  -> push 0
0x99bd39  mov  ecx,[eax+0x14]        ; текущая ширина
0x99bd3c  cmp  ecx,0x400             ; ==1024?
0x99bd45  jne  bd52
0x99bd47  cmp  eax,0x300             ; ==768?
0x99bd4c  jne  bd6a   <-- ПРОПУСК    ; любое другое разрешение -> вызов НЕ выполняется
0x99bd4e  push 1                     ; флаг раскладки 1024x768
0x99bd50  jmp  bd63
0x99bd52  cmp  ecx,0x320             ; ==800?
0x99bd58  jne  bd6a   <-- ПРОПУСК
0x99bd5a  cmp  eax,0x258             ; ==600?
0x99bd5f  jne  bd6a   <-- ПРОПУСК
0x99bd61  push 0                     ; флаг раскладки 800x600
0x99bd63  mov  ecx,esi
0x99bd65  call 0x99fcb0              ; применить раскладку по флагу
0x99bd6a  ...                        ; сюда падают все «неизвестные» разрешения
```

**Диагноз:** у UI ровно **две** раскладки — флаг 0 (800x600) и флаг 1 (1024x768).
При любом другом разрешении (ваше 1600x900, 2560x1440, 3840x2160…) проверка не
проходит, `call 0x99fcb0` **пропускается**, и UI остаётся в дефолтной раскладке 800x600.
Отсюда HUD в верхнем левом «квадрате 800x600», серые/чёрные поля и меню не по центру.
Это и есть те самые «хардверно зашитые старые разрешения».

## ЭКСПЕРИМЕНТ B (готов, 6 байт) — проверить гипотезу

Форсируем флаг=1 (раскладка 1024x768) для любого разрешения:

| file offset | было | стало | смысл |
|---|---|---|---|
| `0x19bd4c` | `75 1c` | `eb 00` | jne bd6a → jmp bd4e (push 1) |
| `0x19bd58` | `75 10` | `eb f4` | jne bd6a → jmp bd4e |
| `0x19bd5f` | `75 09` | `eb ed` | jne bd6a → jmp bd4e |

Скрипт: `work/patch_layout.py` (проверка контрольных байтов, пишет копию
`Etherlords_layout1024.exe`, оригинал не трогает). Уже прогнан: копия собрана,
sha256 копии `179827c6…`.

**Ожидаемый результат при 1600x900:** HUD переедет с привязки «800x600» на привязку
«1024x768» (правый край панелей ~1024, низ ~768). Картинка всё ещё не идеальна
(останутся поля справа/снизу), но это **доказывает механизм** и сразу улучшает вид.

## Почему это потолок «константного» патча и что дальше (Option A)

Раскладок всего две, таблицы координат сверстаны под 800x600 и 1024x768. Значит
«нативная поддержка произвольного разрешения» НЕ достигается правкой констант —
нужен рантайм-хук внутри exe (code cave):

1. Перехватить вход функции позиционирования/отрисовки UI (та, что читает координаты
   из активной раскладки).
2. Масштабировать/смещать координаты из базовой раскладки 1024x768 в реальный
   бэкбуфер: `x' = x * W/1024`, `y' = y * H/768` (или letterbox-центрирование,
   если масштабирование UI даст мыло).
3. Вернуть управление.

Это полноценная, но локализованная работа: один code cave + 1–2 jmp, и она дает
честный native-рендер UI под любое разрешение без внешних DLL. Требует итераций
«правка → ваш скриншот», т.к. рантайм только у вас.

Альтернативы для сравнения:
- **B (сейчас):** 6 байт, раскладка 1024x768 всегда. Быстро, частично.
- **A (цель):** code-cave масштаб UI. Нативно, произвольные разрешения, итеративно.
- **C (внешнее):** dgVoodoo2 — уже известно, не native, вы его не хотите.

## Порядок действий для вас

1. Бэкап `Etherlords.exe`.
2. Положите `Etherlords_layout1024.exe` как `Etherlords.exe` (на машине 1600x900).
3. Скриншоты: главное меню + глобальная карта.
4. Если HUD переехал на привязку 1024x768 — гипотеза подтверждена, начинаем Option A.

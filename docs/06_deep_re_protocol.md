# Deep RE, шаг 1: найти точку записи координат UI-элемента

> **ВНИМАНИЕ (устарело, см. docs/07):** адреса в этом протоколе сдвинуты на +0x400000.
> Настоящие: set_rect = **0x58F690**, apply_layout = **0x59FCB0** (0x98F690/0x99FCB0 не
> существуют — за SizeOfImage). Шаг CE больше не требуется: offsets элементов выведены
> статически (docs/07, §3): record X/Y = `+0x18c+flag*16`, active = `+0x1ac`, rect'ы
> `+0x154/+0x164/+0x174`, маска `+0x150`, relayout = `0x591250`, hit-test = `0x58FB70`.

Цель: обнаружить инструкцию, которая **пишет** X (и Y) правой колонки в объект элемента.
Когда она известна, натив-фикс = масштабировать записываемое значение на
(W/1024, H/768) — и отрисовка с hit-test останутся согласованными, потому что читают
то же поле.

Почему именно «find what writes»: координаты зашиты поэлементно (таблицы под flag 0/1),
глобального design-size нет; статически offsets структуры элемента не вывести однозначно.
Зато запись координаты — одна-две инструкции, и отладчик покажет их точно.

## Опорные значения (из замеров ваших скриншотов)

| Элемент | X при 1024x768 | X при 1600x900 (без патча) |
|---|---|---|
| Правая колонка (портрет/инвентарь) | 870 | 646 |
| Командное колесо | 810 | 586 |
| Нижняя панель (Y) | 742 | 574 |
| Миникарта | 860 | 636 |

## Протокол (Cheat Engine, проще всего)

1. Откат на бэкап `Etherlords.exe` (без моего v1!). Запустить игру, дойти до глобальной карты.
2. CE → выбрать процесс `Etherlords.exe`.
3. В игре поставить разрешение **1024x768** (settings.ini или меню), убедиться, что
   правая колонка справа (X=870).
4. CE: New Scan → Exact Value = **870** (4 bytes, decimal). Сузить до небольшого списка.
   (Если кандидатов много — добавить значение Y=182 соседним扫 scan'ом или фильтром диапазона.)
5. Переключить разрешение на **1600x900** (перезапуск игры/режима; CE-скан переживёт,
   если прикрепить заново после перезапуска; значения станут 646).
6. По найденному адресу(ам): **Browse this memory region → Find out what writes to this
   address**. Вернуться в игру, дёрнуть разрешение/ресайз ещё раз, чтобы сработала запись.
7. CE покажет инструкцию(и) вида `mov [eax+XX], ecx` / `mov [edi+XX], ...`.
   **Скопируйте мне:** адрес инструкции, её байты, и значения регистров в момент записи
   (CE показывает register snapshot), плюс что лежит в `[eax+XX]` до/после.

Альтернатива без CE (x64dbg): брейкпоинт на `Etherlords.0098F690` (set_rect) и на
`Etherlords.0099FCB0` (apply_layout), смотреть аргумент-rect в стеке и this; но «what writes»
в CE быстрее даёт именно offset поля.

## Что я сделаю с этими данными

- Определю offset поля X (и смежных Y/W/H) в объекте элемента.
- Построю code-cave хук ПОСЛЕ записи: читать записанное значение, умножать на
  (W/1024, H/768) по осям, писать обратно — для всех элементов одним обходом или
    точечно в найденной функции, если она общая для всех элементов (вероятно да:
    правая колонка/колесо/низ меняются согласованно).
- Hit-test читает те же поля → кнопки останутся живыми (главный урок v1).

## Заготовка хука

`work/hook_skeleton.py` — генератор патча-трамплина, параметризованный offset'ами
(X_OFF, Y_OFF, W_OFF, H_OFF) и адресом функции-записи. Как только пришлёте offsets/адрес —
подставлю и соберу `Etherlords_native_v2.exe` за один проход.

## Чего НЕ делать

- Не ставить `Etherlords_native.exe` (v1) — ломает hit-test.
- Не править rect (`[esi+0xe8]`) — урок v1: rect читает только миникарта/дата.

## Критерий приемки v2

После применения v2 при 1600x900 нарисованные кнопки стоят **ровно там**, где до патча
возникала hover-подсветка по периметру; hover и click срабатывают в той же зоне.
Повторить на 2560x1440 и 3840x2160. Совпало = draw/hover/click согласованы.

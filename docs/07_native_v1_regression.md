## Уточнённый диагноз

Подмена экран-rect (v1) двигает **только те** элементы, что позиционируются от живого
rect (миникарта, дата). Основная масса UI (правая колонка, колесо, низ, меню) берёт
координаты из **зашитых таблиц раскладки** (flag 0/1), которые rect игнорируют.
Hit-test при этом часть маппинга берёт из rect → после подмены rect отрисовка и hit-test
расходятся → **мёртвые кнопки**.

Вывод: rect — не тот рычаг. Consistent-native требует масштабировать **координаты
элементов** в точке, где их потребляют и отрисовка, и hit-test, то есть после применения
раскладки (`call 0x99fcb0`), пост-обходом списка элементов с масштабированием их x/y/w/h
на (W/1024, H/768). Тогда оба потребителя читают одни и те же поля и расхождения нет.

## Немедленное действие

**Откатитесь на бэкап `Etherlords.exe`.** `Etherlords_native.exe` (v1) не использовать:
ломает hit-test.

## Следующий шаг (если продолжаем deep RE)

1. Локализовать структуру элемента UI: поля x,y,w,h (и указатель next) — по списку,
   который обходит `apply_flag` (`[edi] → +0x1c → …`).
2. Хук после `0x99fcb0`: обход списка, масштаб x,y,w,h на (W/1024, H/768).
3. Проверка: draw и hit-test читают те же поля → кнопки живы, UI нативно растянут.

Это заметно больше работы, чем v1, и требует итераций с отладчиком на вашей стороне
(смотреть значения x/y элементов до/после). Реалистичная оценка — несколько итераций.

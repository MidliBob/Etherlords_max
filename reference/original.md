## Секции (пересчёт file<->va)
| name | va | vsize | rawsize | entropy | pointerToRaw |
|---|---|---|---|---|---|
| .text | 0x1000 | 3491414 | 3493888 | 6.56 | 0x1000 |
| .rdata | 0x356000 | 590857 | 593920 | 4.06 | 0x356000 |
| .data | 0x3e7000 | 317240 | 196608 | 5.08 | 0x3e7000 |
| SGI_STL_ | 0x435000 | 32 | 4096 | 0.07 | 0x417000 |
| .rsrc | 0x436000 | 20080 | 20480 | 4.96 | 0x418000 |

Для `.text`/`.rdata`/`.data`: **VA = file + 0x400000** (ImageBase 0x400000, RVA совпадает
с file offset). Для `SGI_STL_`/`.rsrc`: **VA = file + 0x41e000**.
Листинги docs/02–06 были собраны с неверным базисом (VA = file + 0x800000) — см.
поправку и таблицу соответствия в docs/07, раздел 0.

## Игрового бинарника в репозитории НЕТ (с 0.0.6)

`Etherlords.exe` (анализируемый билд, sha256 `409d3e08…`) **исключён из репозитория**
(untrack-коммит `4a15a78`): проект не распространяет игровой бинарник (дисклеймер
в README). Ранее он лежал здесь «временно — для воспроизводимости анализа»; теперь
эту роль играют отпечаток выше, хеши блоков `blocks/INDEX.md` и сами блоки
`blocks/*.hex` (побайтовые выдержки всех целевых регионов).

Инструменты (`patch_layout.py`, `patch_native_v2/v3.py`, `dump_blocks.py`,
`re_scan.py`, `dd_probe.py`, `verify_original.py`) применяются к **вашей собственной**
копии игры (русская retail 1.07) и отказываются работать с другим билдом по
контрольным байтам/sha256.

Эталонная копия осталась в истории git (коммит `cabb35c` и раньше):

```bash
git checkout cabb35c -- reference/Etherlords.exe   # достать из истории
git restore --staged reference/Etherlords.exe      # снять из индекса (на диске останется;
                                                   # .gitignore не даст ей вернуться в коммит)
```

## Как подать оригинал
1. `python3 tools/verify_original.py /path/to/Etherlords.exe`
2. Сверка sha256 с отпечатком выше и с хешами блоков в `blocks/INDEX.md`.
3. Совпало — offsets/блоки применимы. Не совпало — другой билд, offsets переснять.
